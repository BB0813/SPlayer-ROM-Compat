# Beta90 Android 卡片式播放交互修正方案

## 背景

用户反馈当前“卡片式播放”不合理：点击底部卡片后仍进入旧的播放页/原生接管页，不符合 SPlayer-for-Android PR #15 的移动端卡片式播放器逻辑。PR #15 的核心是底部 Web 播放卡片支持横滑切歌、上滑跟手展开全屏播放器，而不是把旧播放页直接作为卡片内容展示。

## 目标

- Android 默认使用 Web 卡片式播放器作为底部播放入口。
- 底部卡片点击或上滑时打开 Web 全屏播放器，避免默认进入原生播放页接管层。
- 原生播放页接管保留为手动兼容选项，不再作为默认卡片式播放体验。
- 保留原生底部播放卡片能力，但默认切回 Web 卡片，方便验证 PR #15 类交互。

## 实施范围

1. 将 Android 默认 `androidNativePlayerPageEnabled` 调整为关闭。
2. 将 Android 默认 `androidNativeMiniPlayerBarEnabled` 调整为关闭，恢复 Web 底部卡片常驻。
3. 新增设置迁移，已有用户升级到 Beta90 后也默认切回 Web 卡片式播放。
4. 给 `MainPlayer.vue` 补齐 PR #15 的 Pointer 手势：横滑切歌、上滑跟手展开。
5. 更新设置文案，明确原生接管是兼容/降载选项，不是卡片式播放默认方案。
6. 更新版本号、README 与双设备基础验证。

## 风险控制

- 不删除原生播放页和原生底部卡片，只改变默认策略。
- 手势只在手机宽度下启用，平板保持点击打开，避免平板布局误触。
- 保留现有 Android 性能模式的轻量进度条和低负载样式。
