# Beta75 发布命名恢复与原生化 UI 路线

## 目标

- 恢复 Android Release APK 的无编号命名，避免测试用户误以为 `01`、`02`、`03` 是版本或安装顺序。
- 保留三 ABI 独立构建和上传，确保 `arm64-v8a`、`armeabi-v7a`、`x86_64` 仍可分别下载。
- 修正 CI 日志里的中文错误提示，避免乱码影响排查。
- 明确下一阶段 UI 优化与原生化迁移边界。

## 本阶段改动

- Artifact 名称恢复为 `SPlayer-ROM-Compat-arm64-v8a`、`SPlayer-ROM-Compat-armeabi-v7a`、`SPlayer-ROM-Compat-x86_64`。
- GitHub Release 附件名称恢复为 `SPlayer-ROM-Compat-<tag>-<abi>.apk`。
- Release 资产准备步骤不再复制出带编号前缀的文件。
- README 同步更新到 `v3.0.0-rc.3-Beta75`。

## 关于全原生化

全原生化能解决或缓解的问题：

- 播放时 WebView 主线程被状态刷新、歌词滚动、列表渲染拖慢。
- 手机和平板安全区、导航栏、状态栏、横竖屏与高 DPI 适配不稳定。
- 原生音频控制、后台保活、系统通知卡片与 ROM 策略耦合不足。
- 触控目标、滑动冲突、页面边界拖拽等 Web 容器问题。

全原生化不能自动解决的问题：

- 组件层级混乱。
- 视觉密度不统一。
- 播放控件和底部导航的交互优先级不清晰。
- 字号、间距、卡片比例缺少统一设计令牌。

## 后续建议

- Beta76：先定统一移动端设计令牌，限制字号、间距、圆角、阴影和底栏高度。
- Beta77：优先原生化播放页与底部播放控制，降低播放状态刷新对 Web UI 的影响。
- Beta78：原生化列表容器与滚动边界，解决歌单、首页、发现页在不同 DPI 下的错位。
- Beta79：原生化设置页核心控件，统一滑块、开关和弹窗触控体验。
