# Beta82 Android 原生播放进度同步拆分计划

## 目标

- 进一步降低播放时 WebView 到 Android 原生层的状态同步频率。
- 避免单纯播放进度变化反复触发原生播放页和原生底部卡片的 Bridge 更新。
- 让原生播放页和原生底部卡片优先使用 AndroidNativeAudioPlayer 本地进度读取。
- 保留歌曲切换、播放状态、缓冲状态、歌词行变化和显示隐藏等必要同步。

## 用户反馈

- 播放音乐后普通页面仍可能受到播放状态刷新影响。
- 底部播放卡片已经原生化，但如果 Web 继续同步每次进度变化，仍会产生不必要的桥接压力。
- 播放页歌词和进度需要稳定，但不应该拖慢首页、歌单页和设置页。

## 本阶段改动

- 原生全屏播放页遇到 progress-only 更新时不再走 Web 到 Native 的完整状态同步。
- 原生底部播放卡片遇到 progress-only 更新时不再走 Web 到 Native 的完整状态同步。
- 进度显示改由原生 View 内部的 progressTicker 直接读取 AndroidNativeAudioPlayer。
- 歌词行、歌曲信息、播放/暂停、缓冲状态和可见性变化仍继续同步。
- 移除 Beta81 中针对 progress-only Bridge 节流的冗余计时状态。

## 验证重点

- 播放时首页、歌单页、设置页是否减少卡顿。
- 原生底部播放卡片进度是否仍能正常前进。
- 原生全屏播放页进度条和时间是否仍能正常前进。
- 切歌、暂停、恢复播放、打开/关闭播放页是否仍能同步。
- 歌词行变化是否仍能同步到原生播放页。

## 后续计划

- Beta83 继续把原生底部卡片补齐拖拽进度条和队列入口。
- Beta84 继续优化平板横屏下原生播放控制区排版。
- Beta85 评估更多播放页歌词状态下沉到原生层。
