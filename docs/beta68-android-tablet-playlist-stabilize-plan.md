# Beta68 Android 平板歌单页排版加固方案

## 目标

- 修复平板端歌单页详情头部、歌曲列表和底部播放栏之间仍存在错位、挤压或空白的问题。
- 统一 CSS 实际高度与 JS 列表高度扣减值，避免详情头部 padding 被重复计算后挤压歌曲列表。
- 让歌单页在平板横屏、平板竖屏和高 DPI 虚拟机下都能保持稳定宽度和高度。

## 根因

- `ListDetail.vue` 内部详情头部使用 `height` 加 `padding`，默认盒模型为 content-box，实际占用高度大于 JS 中扣减的高度。
- `SongList.vue` 的平板横屏识别依赖根节点 class，缺少窗口尺寸响应，切换平板横竖屏或首次挂载时可能沿用错误行高。
- 歌单页没有在平板场景下明确把 `playlist-list`、`list-detail`、`song-list` 组成稳定的纵向 flex 链路，极端尺寸下更容易出现列表区域被挤压。
- 歌曲行高、列表头高度和虚拟列表滚动索引没有完全共用同一套动态高度。

## 实现

- 为 Android 平板歌单页补充统一 CSS 变量：详情头部高度、滚动后头部高度、列表表头高度、歌曲行高和底部安全 padding。
- 将平板歌单详情头部改为 border-box，高度包含 padding，避免 JS 和 CSS 计算不一致。
- 平板横屏详情头部进一步收紧封面、标题、菜单和元信息高度，防止头部过高挤压歌曲列表。
- `SongList.vue` 改为基于 `useWindowSize()` 响应式识别 Android 平板横屏/竖屏，并让行高、表头和底部 padding 随尺寸同步变化。
- 列表滚动索引改用当前实际歌曲行高，避免平板端“回到当前播放歌曲”时定位错位。
- 给平板歌单页补充纵向 flex 稳定链路和横向溢出保护。
- 版本号更新到 `3.0.0-rc.3-Beta68`。

## 验证重点

- 平板 `192.168.1.167:5555` 横屏进入歌单页后，详情头部不再过高，歌曲列表首屏可见且不被底部播放栏遮挡。
- 平板端歌单页不能出现横向拖拽、异常长条、列表只剩一行或大块空白。
- 手机 `192.168.1.128:5555` 歌单页不回退，窄屏布局仍保持可用。
- 播放状态下切换歌单页，列表高度稳定，底部播放条和导航栏不裁切歌曲行。
