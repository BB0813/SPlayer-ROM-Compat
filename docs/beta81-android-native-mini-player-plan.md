# Beta81 Android 原生底部播放卡片接管计划

## 目标

- 将 Android 底部迷你播放卡片从 WebView 中进一步拆出来。
- 播放时减少 Web 底栏常驻组件、阴影、歌词和进度状态刷新带来的压力。
- 保留移动端最常用的播放入口和核心控制。
- 为后续全原生播放控制区打基础。

## 用户反馈

- 播放音乐后首页、歌单页、设置页仍可能被播放器状态拖慢。
- 底部卡片式播放更符合移动端习惯，但 WebView 内部渲染仍有成本。
- 测试用户需要稳定、够大的播放控制，不希望每次播放都牵动整个页面重绘。

## 本阶段策略

- 新增 Android 原生底部迷你播放卡片 View。
- 复用现有播放状态 Bridge，不新建独立播放器逻辑。
- 原生卡片仅承载封面、歌曲名、歌手、上一首、播放/暂停、下一首和轻量进度。
- 原生卡片点击非按钮区域打开原生播放页。
- Web 侧在原生卡片启用时隐藏 Web 底部播放卡片，避免双重渲染。
- 进度由原生层从 AndroidNativeAudioPlayer 读取并低频刷新，减少 Web 状态依赖。

## 验证重点

- Android 性能模式下底部原生卡片是否显示在底部导航上方。
- 主页、歌单页、设置页播放时是否减少卡顿。
- 上一首、播放/暂停、下一首和点击打开播放页是否正常。
- Web 底部播放卡片是否不会和原生卡片同时显示。
- 全屏原生播放页是否仍能正常打开和关闭。

## 后续计划

- Beta82 继续把播放页歌词状态同步拆成稳定状态和进度状态。
- Beta83 评估原生底部卡片加入队列入口和拖拽进度条。
- Beta84 继续做平板横屏下的原生播放控制区适配。
