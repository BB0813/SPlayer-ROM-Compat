# Beta83 Android 原生底部卡片交互补全计划

## 目标

- 补齐原生底部播放卡片的实用交互。
- 将轻量进度条升级为可拖拽 SeekBar。
- 增加播放队列入口，减少用户回到 Web 控件找队列的操作成本。
- 继续保持播放进度由原生层读取，避免恢复高频 Bridge 同步。

## 用户反馈

- 卡片式播放方向可用，但底部控件需要继续补完整。
- 播放进度最好可以直接拖拽，而不是只能显示。
- 播放队列入口是常用操作，不应该被原生化阶段遗漏。

## 本阶段改动

- 原生底部播放卡片进度条由 ProgressBar 改为 SeekBar。
- 用户拖动原生进度条时直接调用 AndroidNativeAudioPlayer.seek。
- 拖动过程中暂停本地 progressTicker 覆盖，松手后恢复本地进度刷新。
- 原生底部播放卡片新增“队列”按钮。
- Android 控制事件新增 openPlayList 处理，原生按钮可直接打开或关闭播放队列。
- 保持歌曲信息、播放状态和可见性变化走 Bridge，同步纯进度仍由原生层接管。

## 验证重点

- 原生底部播放卡片进度条是否可以拖拽并跳转播放位置。
- 拖拽后进度是否继续自动前进。
- 队列按钮是否能打开和关闭播放队列。
- 上一首、播放/暂停、下一首是否不受影响。
- 播放中首页、歌单页、设置页是否仍保持 Beta82 的低同步压力。

## 后续计划

- Beta84 继续优化平板横屏下原生播放控制区排版。
- Beta85 评估把更多歌词状态下沉到原生层。
- Beta86 继续处理国内 ROM 上原生卡片与系统媒体控制的状态一致性。
