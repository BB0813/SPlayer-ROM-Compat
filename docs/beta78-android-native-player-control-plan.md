# Beta78 Android 原生播放页接管与播放控件减负

## 目标

- 降低播放时首页、歌词页和底部播放控制的 Web 渲染压力。
- 让 Android 全屏播放页优先由原生层渲染，减少 WebView 中复杂歌词和背景动效开销。
- 保留 Web 端状态源，避免一次性重写播放队列、歌词解析和登录逻辑。

## 问题定位

- 原生播放页 View 已存在，但设置默认关闭，实际发布包仍主要依赖 Web 全屏播放页。
- 原生播放页状态中 `currentTime` 与 `duration` 直接传入 Store 毫秒值，而 Android 原生播放器接口使用秒，存在进度显示和拖拽单位不一致风险。
- 原生播放页进度依赖 Web 状态同步，播放时如果 Web 降频，进度显示会变慢。

## 本阶段改动

- Android 默认启用原生播放页接管，并通过设置迁移覆盖旧版本 Android 默认值。
- Web 全屏播放页在 Android 原生播放页接管开启时不再渲染，只保留原生覆盖层。
- 原生播放页状态同步改为秒单位，Web Store 仍保持毫秒单位。
- Android 恢复原生播放状态时将秒转换回毫秒，避免重启后进度异常。
- 原生层增加 500ms 进度刷新器，播放中直接读取 `AndroidNativeAudioPlayer` 的当前时间和总时长。
- Web 到原生播放页的歌词和进度同步增加低频节流，减少无意义重复刷新。

## 验证重点

- 手机和平板进入全屏播放页时是否显示原生播放页。
- 播放、暂停、上一首、下一首、拖动进度条是否正常。
- 播放时首页、歌单页、设置页切换是否比 Web 全屏播放页更稳定。
- 播放到结尾自动切歌后原生播放页进度和按钮状态是否保持同步。

## 下一阶段

- 继续下沉底部迷你播放控制，减少主界面播放时的 Web 组件刷新。
- 对歌词数据和评论数据做缓存兜底，降低网络失败对 UI 的影响。
- 根据双虚拟机实测结果微调原生播放页的手机和平板布局。
