# Beta67 Android 播放页横滑与双端验证方案

## 目标

- 修复 Android 全屏播放页从播放页左滑到歌词页、从歌词页右滑返回播放页不稳定的问题。
- 区分横向切页手势与歌词纵向滚动，避免歌词列表或系统 WebView 抢走横滑。
- 将测试流程固定为手机和平板双端安装验证：`192.168.1.128:5555` 与 `192.168.1.167:5555`。

## 根因

- 当前播放页依赖 `touchmove` 后置判轴，根节点仍声明 `touch-action: pan-x pan-y`，Android WebView 可能先接管横向默认手势，导致 `touchcancel` 或 `touchend` 丢失。
- 歌词容器的触摸事件不区分横向与纵向，横滑歌词页时也会被标记为用户滚动，干扰自动歌词滚动恢复。
- 旧逻辑在判定横向后主动向子元素派发 `touchcancel`，在部分 ROM/WebView 上容易让子组件和父级手势状态不同步。
- 手机和平板都走 `FullPlayerMobile.vue`，因此同一套手势逻辑必须兼容窄屏手机、高 DPI 平板和横竖屏。

## 实现

- 播放页改用 Pointer Events 作为主链路，使用轴锁和 `setPointerCapture` 保证横滑过程不会被子组件抢走。
- 保留 Touch Events 作为旧 WebView 兜底，但在支持 Pointer Events 的环境中不重复执行。
- 横向切页阈值按视口宽度动态计算，并加入快速滑动判定。
- 根播放页 `touch-action` 收敛为 `pan-y`：纵向滚动交给浏览器，横向切页交给播放页手势逻辑。
- 歌词容器只在纵向移动时标记用户滚动，横向移动留给播放页切页。
- 增加播放页 `data-page-index`，便于 ADB 截图和后续调试定位当前页。
- 版本号更新到 `3.0.0-rc.3-Beta67`。

## 验证重点

- 手机 `192.168.1.128:5555` 安装后能启动，播放页左滑进入歌词页、右滑返回播放页。
- 平板 `192.168.1.167:5555` 安装后能启动，横竖屏下播放页切页不丢手势。
- 歌词页纵向滚动仍可用，横滑时不触发歌词滚动冻结。
- 进度条、播放/暂停、上一首、下一首等控制按钮不被横滑手势误拦截。
- 安装启动后检查版本号、进程状态和崩溃日志。
